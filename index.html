Installation

Prepare the machine. Then connect.

The current documented installation uses an authorized source checkout. Public executable packages and APT/Homebrew distribution are being prepared; no public binary download is advertised here yet.

Before you begin

Source access must be provided by the project administrator. Use your normal OS account, not root, for the gateway's user services. Keep the installation directory available: services use it as their working directory.

What you need

  • macOS or Ubuntu. Homebrew must already be available on macOS. On Ubuntu, package installation may ask for your sudo password in the terminal.
  • Python 3.12 or 3.13 and uv. Use the committed lockfile for a repeatable Python environment.
  • Node.js 22.12+ and npm when building Web Admin and Web User from source. Node.js is not needed to serve already-built web assets.
  • PostgreSQL and Codex App Server. Setup can prepare supported local dependencies. Complete Codex login and endpoint configuration before starting gateway services.
  • Internet access and sufficient local permissions. Setup may install packages and prepare application configuration. Optional integrations can require separate provider accounts.

1. Install the project dependencies

Open a terminal in your authorized gateway checkout—the directory containing pyproject.toml.

uv sync --frozen

2. Run the setup wizard

uv run codexgate setup

The default all flow prepares Codex, PostgreSQL, Centrifugo, Evolution API, Garage, and plugins. PostgreSQL setup creates a missing dedicated login/database and runs migrations. It preserves an existing role and password rather than resetting them. You can configure individual components instead; see setup options.

Private bootstrap values are saved in .env. Keep that file private. Runtime configuration is managed through the gateway's database-backed settings where supported. The current service installer requires this source checkout, uv, and Python; standalone executable installation has not been verified. Setup does not start the gateway services.

3. Build the web applications

uv run codexgate web setup
uv run codexgate web build --target user
uv run codexgate web build --target admin

Build both targets if they were not supplied with your installation. Web builds produce static assets; they do not restart running services.

4. Register and start the user services

Complete Codex login and select the intended App Server connection first. Then register the gateway and Admin separately.

uv run codexgate service install
uv run codexgate admin service install
uv run codexgate service start
uv run codexgate admin service start
uv run codexgate service status
uv run codexgate admin service status

Web Admin listens on its configured bind host/port; the default is http://127.0.0.1:8767. The API default is 127.0.0.1:8765. Configure the gateway public URL in Web Admin before pairing devices through a public address. The Admin address is separate from that public URL.

5. Pair your first device

uv run codexgate pair --qr
uv run codexgate pairings --status pending
uv run codexgate verify <pairing_id>

Replace placeholders with the IDs returned by your gateway. Check the requesting device and comparison information before approval. Add --manage-gateway to verification only if that device should administer the gateway.

CLI reference

A command for each job.

Examples below use uv run codexgate from the source checkout. The command name is codexgate; uv run selects its project environment. Commands that print structured output support --json where noted.

setup [component]

Prepare an installation or a selected dependency. Omitting the component selects all. Existing configuration is reused; setup is not a gateway service restart.

Setup components
ComponentPurpose
allPrepare Codex, PostgreSQL and migrations, Centrifugo, Evolution, Garage, and plugins.
codexCheck or install the supported local Codex CLI. Login remains a separate operator action.
postgresPrepare the local PostgreSQL login/database and apply migrations.
centrifugoPrepare realtime configuration; a shared service may require a separate reload.
evolutionConnect or prepare the native Evolution API used for WhatsApp.
garagePrepare local S3-compatible storage and its connection profile.
blender · remotionPrepare the selected local application's requirements.
pluginsInstall gateway plugin packages; repeat --plugin to select plugins.
instructionsPrepare gateway-managed workspace instructions.
nginxGenerate a proxy template, or explicitly prepare an inactive site configuration.
checkInspect setup status without installing components.
uv run codexgate setup check
uv run codexgate setup postgres
uv run codexgate setup plugins --plugin codexgate-tool
uv run codexgate setup centrifugo --centrifugo-config /path/to/config.toml
uv run codexgate setup nginx --domain gateway.example.com

--yes uses existing settings/defaults without the wizard; review configuration first. Nginx options include --target gateway|storage|garage, --mode template|install, --output, upstreams, listen port, and TLS certificate/key paths. Use setup --help before preparing a site; generation is not proxy activation.

migrate

Apply pending Alembic migrations to the configured database. Setup runs this as part of PostgreSQL preparation; updates should run it explicitly after stopping gateway services.

uv run codexgate migrate

A database connection and the migration files from the installed version must be available. If migration fails, resolve the reported error before starting that version.

service <action>

Manage the gateway's native user service. macOS uses launchd; Ubuntu uses the user's systemd service. Registration and startup are separate actions.

Gateway service actions
ActionBehavior
installRegister without starting. Optional --project-dir selects the installation directory.
start · stop · restartStart, stop, or restart the gateway supervisor and its owned processes.
statusShow service status. Add --json for machine-readable output.
restart-apiRestart only the API workers.
restart-runtimeRestart only Runtime Codex.
restart-whatsappRestart only Runtime WhatsApp.
restart-automationRestart only Runtime Automation.
restart-toolsRestart only Runtime Tools.
restart-third-partyRestart only Runtime Third Party.
uninstallRemove the native gateway service registration; not a database deletion.
uv run codexgate service status --json
uv run codexgate service restart-api

All listed service actions accept --json. restart-runtime controls the gateway runtime, not the separate Codex App Server daemon. Web Admin has its own service below.

admin

admin serve runs Web Admin in the foreground. admin service manages its independent native user service.

uv run codexgate admin service install
uv run codexgate admin service start
uv run codexgate admin service status --json
uv run codexgate admin service restart

Available service actions: install, start, stop, restart, status, and uninstall. Each accepts --json; install also accepts --project-dir. Restarting Admin does not restart the gateway API or its runtimes.

web

web setup installs exact frontend dependencies with npm. web build builds the selected React application without restarting services.

uv run codexgate web setup
uv run codexgate web build --target user
uv run codexgate web build --target admin --install

--target accepts user or admin and defaults to user. --install forces dependency installation before build. Source builds need Node.js 22.12+ and npm.

pair

Create a short-lived pairing invitation. Use --qr to display a QR in the terminal, or --json for structured output; the two flags are mutually exclusive.

uv run codexgate pair --qr

pairings

List pairing history and IDs. Filter with --status all|pending|approved|revoked; default is all. Optional --json returns structured output.

uv run codexgate pairings --status pending

devices

devices and devices list show registered devices. Grant or remove gateway-management permission without re-pairing using an exact device UUID.

uv run codexgate devices list
uv run codexgate devices grant <device_id> --manage-gateway true
uv run codexgate devices grant <device_id> --manage-gateway false

Device listing and grant accept --json. Grant explicitly requires --manage-gateway true|false.

verify <pairing_id> alias: approve

Approve one exact pending pairing. Add --manage-gateway only when management access is intended. Optional --json returns the result.

uv run codexgate verify <pairing_id>
uv run codexgate approve <pairing_id> --manage-gateway

reject <pairing_id>

Reject one pending pairing request. Accepts --json.

suspend <device_id>

Suspend an existing device's gateway access. Accepts --json.

revoke <device_id>

Revoke the selected device's gateway access. Confirm the exact device before executing. Accepts --json.

reactivate <device_id>

Create a new pairing invitation for an existing device. This is not immediate approval. Accepts --json.

app-servers

Discover local Codex App Servers without stopping or restarting them. Add --json for structured discovery, --pid for one process, or --use-socket to save a discovered local Unix endpoint into .env.

uv run codexgate app-servers --json
uv run codexgate app-servers --use-socket

Advanced option --show-token requires --pid and can reveal a private token. Do not use it for ordinary discovery or share its output.

s3

Manage encrypted S3 connection profiles. Private JSON files are read locally; do not put credentials in shell arguments or public documentation.

S3 profile commands
CommandPurpose
s3 key-initInitialize the local master key without printing or replacing an existing key.
s3 profilesList profile metadata without credentials.
s3 put <name> --file <path>Create a profile from an owned private JSON file. Gateway generates its stable ID; duplicate names are rejected.
s3 delete <profile_id>Remove the stored profile through the gateway lifecycle; provider resources are left unchanged.

The input file must be an owned private regular file, at most 64 KiB. --file - reads JSON from standard input.

plugins settings

Inspect and patch provider configuration stored in PostgreSQL. Secret values remain hidden when reading configuration.

Plugin configuration commands
CommandPurpose
plugins settings listList provider configuration metadata.
plugins settings show <plugin_id>Read configuration with secret values hidden.
plugins settings set <plugin_id> --file <path>Patch values from a private JSON file; - selects standard input.
plugins settings import-envImport missing legacy provider settings. Optional --remove-env removes migrated legacy keys from local .env only after successful import.

These are configuration commands, not Codex plugin package installation. Use setup plugins to install plugin packages. Use Web Admin for profile connection/OAuth where supported.

Foreground processes

Use these for explicit foreground operation and diagnostics. Do not run duplicate processes against an already-managed installation. Normal installations should prefer service start.

Foreground commands
CommandRuns
superviseThe gateway supervisor and its owned API/runtime processes.
serveThe HTTP API using configured settings.
runtimeThe singleton Codex runtime on its private Unix socket.
whatsapp-runtimeThe isolated WhatsApp runtime.
automation-runtimeThe isolated automation runtime.
third-party-runtimeThe isolated third-party application runtime.
tools-runtimeThe allowlisted runtime-tools process.

Web Admin's foreground equivalent is admin serve. Gateway runtimes and the external Codex App Server are separate lifecycle owners.

Updates

Stop. Migrate. Start.

For an authorized source installation, update code and dependencies while gateway services are stopped. There is currently no codexgate upgrade command or published APT/Homebrew update channel.

  1. Check the release notes and preserve configuration.

    Use the intended installation directory and OS account. Keep .env, encryption keys, database data, workspace files, and runtime configuration. Resolve local source changes before updating.

  2. Stop both gateway services.
    uv run codexgate admin service stop
uv run codexgate service stop
  3. Update the authorized checkout and environment.
    git pull --ff-only
uv sync --frozen
uv run codexgate web build --target user --install
uv run codexgate web build --target admin

    Use your administrator's release checkout instructions when deploying a specific tag. Rebuild web assets if the new version does not already include them.

  4. Apply database migrations.
    uv run codexgate migrate

    This flow does not create an automatic database backup. If migration fails, leave services stopped and resolve the reported problem before proceeding. Do not attempt an automatic schema rollback.

  5. Start the gateway and verify it.
    uv run codexgate service start
uv run codexgate admin service start
uv run codexgate service status
uv run codexgate admin service status

    Confirm API /health/live and /health/ready at your configured gateway address, then open Web Admin and confirm the version. If a release changed plugin definitions or skills, run the selected setup plugins and reload MCP as directed by its notes.

Gateway restart means gateway processes.

Do not manually restart an external Codex App Server daemon or unrelated PostgreSQL, Centrifugo, storage, or tunnel services as an automatic part of this procedure. Gateway-owned managed processes follow the configured lifecycle. Follow a release's explicit instructions if it requires such a change.
